## Cross-cutting patterns（多人從不同角度撞到同個 root cause）

### A. 缺 data-access abstraction → 修一個地方要動 N 處
- Architecture: 30+ 處 raw `.from("xxx")`、`profiles.role` 在 **7 處**重複查詢 `[SOURCE: arch.md "Critical 3"]`
- Coding style: `requireVendor()` pattern 在 `vendor/menu/actions.ts` 已抽出，但 `vendor/{orders,profile,revenue}/actions.ts` + `api/pickup/route.ts` 各自手寫一遍 `[SOURCE: style.md "Critical 3"]`
- Security: addToOrder / pickUpOrderItem 重複 auth boilerplate，每處都是潛在漏洞
- **最小成本修法**：把 `requireVendor()` 升格到 `lib/auth.ts`，回 `{ user, supabase, vendor }`；同時加 `requireUser()` 替三個 user-action 統一 boilerplate

### B. `addToOrder` 是漏洞 + 缺測雙重災區
- Security 列了 3 條 finding（價格、qty、slot×menuItem cross-check）
- Testing 列為 critical：「整個系統 demand 最高的入口，逐字無測試」
- **同一個 server action 是 oversell 防線 + 價格信任邊界 + 商品-slot 對應檢查邊界**
- 修上面 #1 + #4 + 補 mock 測試 → 一次解三條

### C. `addToOrder` 之外，shop 端三個共用 auth pattern 全裸測
- `requireRole` / `pickUpOrderItem` / `recommendation.ts` 三函式都是被廣泛依賴但零測 `[SOURCE: testing.md]`
- 加 `requireRole` 測試成本最低（純函式 + mock supabase）— 應該作為 quick win

### D. Token 系統「定義完整 vs 落地稀薄」
- UI/UX agent：globals.css token 完整落地，但 component 端 `text-(xs|sm|...)` legacy scale 144 處 vs token 37 處（~20% 對齊）`[SOURCE: uiux.md]`
- Documentation agent：`.claude/rules/uiux.md` 跟 `DESIGN.md` 對圓角規則**直接打架**，且都被 auto-load chain 讀進來 → agent 不知該聽誰 `[SOURCE: doc.md "Critical"]`
- **本質**：DESIGN.md 是 Draft v0.1，自稱 SSoT 但**不在 CLAUDE.md auto-load chain**，舊規則 uiux.md 還在發號施令
- 修法：(1) 刪除 `.claude/rules/uiux.md` 或改為 link to DESIGN.md；(2) `CLAUDE.md` 加 `@DESIGN.md`；(3) 跑 codemod 批量替換 legacy class

### E. Vendor / Admin 兩套 chart 元件 90% 重複
- Coding style: `app/admin/{trend,bar}-chart.tsx` vs `app/vendor/revenue/revenue-{trend,bar}-chart.tsx` 逐行對齊
- Architecture 也提了 recommendation.ts 內三函式的類似重複
- 修法：抽 `components/chart/{trend,bar}-chart.tsx` 泛型化，data row + label formatter 用 prop 傳

### F. 三軌 auth 不對稱
- Architecture：admin/vendor 有 layout guard，user route 沒有，全靠 `proxy.ts` 兜底
- Security：proxy 是 edge layer 守正、但若 PostgREST 端點不過 proxy（advisors 也有提）就裸奔
- 修法：建 `app/(user)/` route group + layout guard，三軌對稱

## What's good — 報告可用亮點

照學期評分權重排（架構 25% / 測試 25% / 需求 30% / 程式碼 10% / 運維 10%）：

### 架構 / DB 設計（25%）
- **RLS 是真實的權限執行層**，22 條 policy 覆蓋全 12 張表，且用 `(SELECT auth.uid())` 觸發 initplan optimization 避開 per-row 重算 `[SOURCE: 20260328124225_*.sql]`
- **Slot-limiting 走 DB CHECK + Postgres trigger**，把 race condition 推到 DB level，應用層 INSERT-only + catch `23514` 翻成「此日期已售完」`[SOURCE: docs/highlights/slot-limiting.md]`
- **雙層 auth defense-in-depth**：layout guard + Server Action `requireRole()`，繞過 layout 也擋
- **Server Component / Server Action 分工乾淨**：22 個 page/layout 全 Server Component，無 `useEffect` + fetch antipattern
- **加新 role 擴展點明確**：4 步可加新角色，沒有 hard-code role 跑遍 codebase

### 測試 / 驗證（25%）
- **Pure function 抽出 + co-located test 是教科書級 testable architecture**：`cart-view` / `order-summary` / `revenue-model` / `navigation-rules` 共 16 個 case，DB query 在 action 裡、純邏輯抽出來測
- **`createSupabaseMock` factory 設計可複用**，新加 server action test 的 marginal cost 低
- **Pagination off-by-one 有測**：`getOrders` 的 `hasMore` (fetch limit+1) 有對應 test
- **E2E 覆蓋 critical happy path**：「首頁可見 → 菜單瀏覽 → 加車 → 結帳 → 訂單已確認」

### 安全（含在 25% 運維）
- **所有 11 張 public table RLS enabled**
- **所有 SECURITY DEFINER function 都 `SET search_path TO 'public'`** 防 search_path attack
- **無 `service_role` 洩漏** — codebase 任何角落都 grep 不到
- **`auth/callback/route.ts` 對 `next` 參數做了 `startsWith("/") && !startsWith("//")` 防 open redirect**
- **`pickup/route.ts` 三段驗證**：vendor role → vendor 擁有 → order_item 屬於該 vendor → status confirmed → 才標 picked_up

### 程式碼品質（10%）
- **零 `any` / 零 `as any`** — TypeScript 專案非常難得
- **零 antipattern markers** — 沒有 `for simplicity` / `TODO` / `FIXME` / `HACK`
- **`try-catch` 完全沒出現**，所有 server action 走 `{ ok, error }` 物件，錯誤處理一致不過度防禦
- **`'use client'` 使用克制**：34 處都對應到實際 interactivity 需求

### UI/UX（運維 10%）

- **首頁 `<HomePage>` 完整對齊 DESIGN.md** — 是其他頁面的範本
- **每個 route 都有 `loading.tsx`** — 11 個 route 全覆蓋
- **`next-themes` + `defaultTheme="light"` + `enableSystem`** — dark mode 基礎建設完成

### 2. Supabase advisor 11 個 security WARN（security agent 部分重疊但 advisor 更全）
- 2 個 **public_bucket_allows_listing**：`menu-item-images` / `vendor-images` 的 SELECT policy 太寬，clients 可 list 整個 bucket
- 8 個 **(anon|authenticated)_security_definer_function_executable**：`handle_new_user` / `is_admin` / `is_vendor_order` / `update_reserved_qty` 四個 SECURITY DEFINER function 都可被 `anon` 或 `authenticated` 透過 `/rest/v1/rpc/<fn>` 直接呼叫 — 應該 `REVOKE EXECUTE FROM anon, authenticated`（這些是 trigger function / 內部 helper，不該對外）
- 1 個 **auth_leaked_password_protection**：HaveIBeenPwned 整合沒開（如果 email/password 登入路線會用）
